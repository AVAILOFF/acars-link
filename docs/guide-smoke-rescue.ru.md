# Дым и аварийные службы: подробный гайд для вас

Этот документ — всё, что нужно сделать **вам** руками, чтобы в симуляторе появились:

1. **дым у ВПП назначения** (задача T34) — код готов, не хватает визуального эффекта и пакета для MSFS;
2. **пожарные машины и скорая по прилёту** (задача T54) — кода ещё нет, сначала нужны данные, которые
   можно получить только в симуляторе.

Каждый шаг описан так: что сделать → что должно получиться → что делать, если не получилось.
Пометка **[?]** значит, что в документации SDK этого нет или это никто не проверял. Запишите, что вы
увидели на самом деле, — это и есть результат.

Состояние на 2026-10-15.

## Часть 0. Как это устроено

### Дым

```
сценарий dest_fire (ядро)
   │  за ~120 NM до назначения, с вероятностью 2 % (или вручную «Запустить сейчас»)
   │  телекс FIRE REPORTED NEAR RWY …  +  шаг «smoke: start»
   ▼
приложение (controller.ts)
   │  находит середину плановой ВПП в OurAirports runways.csv
   │  отправляет мосту smoke_start {lat, lon}
   ▼
мост acars-msfs-bridge (ws://127.0.0.1:47830)
   │  запоминает точку
   │  самолёт ближе 40 NM  → AICreateSimulatedObject("ACARS Smoke", lat, lon, на земле)
   │  дальше 60 NM, smoke_stop, 90 минут, выход из MSFS → AIRemoveObject
   ▼
MSFS: невидимый объект «ACARS Smoke» из нашего пакета (в Community)
   │  его XML запускает визуальный эффект дыма (по InstanceID)
   ▼
столб дыма у ВПП, снос по ветру — силами самого эффекта
```

Важно понимать три вещи:

- **Приложение и мост уже всё умеют.** Не хватает только того, что делается в редакторе MSFS: самого
  эффекта дыма и пакета с объектом `ACARS Smoke`. Без пакета мост пытается создать объект, MSFS его не
  находит, и вы видите ошибку `CREATE_OBJECT_FAILED`.
- **Мост ветер не передаёт.** Дым наклоняется по ветру, только если так собран эффект (узел `WindDirection`).
- **Объект создаётся только на 40 NM**, хотя телекс приходит на 120 NM. Дальше MSFS всё равно не грузит
  объекты, а лишний объект стоил бы FPS.

### Аварийные службы (как будет после T54)

```
сценарий MAYDAY / PAN / пожар в кабине / медицина
   │  шаг «rescue: full | standby | medical»
   ▼
приложение: порог и курс ВПП посадки (OurAirports) + список машин из настроек
   │  rescue_start {level, rwy, count, titles}
   ▼
мост (RescueController)
   ≤ 15 NM  → машины появляются сбоку от ВПП (45 м от оси, 70 м между ними, 100 м от порога)
   касание  → едут за самолётом (только full), 25 м позади
   стоп     → окружают самолёт по кругу радиусом 50 м
   +10 мин  → исчезают (или дальше 30 NM — уход на второй круг)
```

Машины — это **стандартные объекты MSFS** (как в моде Emergency Response On Demand), своего пакета для них
делать не нужно. Но надо точно знать их названия, иначе мост не сможет их создать. Это и есть ваша главная
работа по T54 (часть 4).

## Часть 1. Подготовка компьютера

Делается один раз, нужно и для дыма, и для машин.

### 1.1. Developer Mode в MSFS 2024

1. Запустите MSFS 2024.
2. **Options → General Options → Developers → Developer Mode = ON**.
3. Сверху появится полоса меню DevMode (File, Edit, View, Tools, Debug, Help…). Если её не видно, наведите
   мышь на верх экрана.

### 1.2. MSFS 2024 SDK

1. DevMode → **Help → SDK Installer**, скачайте и установите SDK. Запомните путь, например
   `C:\MSFS 2024 SDK`.
2. Пример **SimpleFX** (дым двигателя) в основной SDK **не входит**, примеры скачиваются отдельно:
   DevMode → **Help → Samples** → установщик **«Samples»** (основной, не «Xbox Samples» и не «DA62»).
   Установите его, затем найдите на диске файл `SimpleFX.xml` (поиск Windows по имени, обычно внутри
   папки SDK, раздел `Samples\DevmodeProjects`) и запомните путь. У вас SDK стоит в `D:\MSFS 2024 SDK`
   (проверено 2026-10-15: примеров там пока нет).

**Если установщика нет в меню Help:** SDK можно скачать со страницы документации SDK
(docs.flightsimulator.com → MSFS 2024 → SDK). Путь потом укажите при сборке моста (шаг 1.3).

### 1.3. Собрать мост с поддержкой SimConnect

В папке репозитория:

```bash
pnpm bridge:build
```

В выводе найдите строку:

```
acars-msfs-bridge: SimConnect support ON (…)
```

- **ON** — всё хорошо.
- **OFF** — сборка не нашла SDK. Укажите путь явно:

```bash
dotnet build bridge/msfs -p:MsfsSdk="C:\MSFS 2024 SDK"
```

  Чтобы не писать путь каждый раз: скопируйте `bridge/msfs/Local.props.example` в `bridge/msfs/Local.props`
  и впишите путь туда. Этот файл не попадает в git.

Готовый мост лежит здесь:

```
bridge\msfs\src\AcarsBridge\bin\Debug\net8.0\acars-msfs-bridge.exe
```

**Приложение мост само не запускает.** Его нужно запускать вручную перед каждым полётом (часть 3).

### 1.4. Проверить, что мост видит симулятор

1. MSFS: начните любой полёт (на стоянке).
2. Запустите `acars-msfs-bridge.exe --verbose`. Окно не закрывайте.
3. Запустите приложение:

```bash
pnpm desktop
```

4. В приложении, в строке статуса **«Мост симулятора»**, должно быть: подключён, источник `simconnect`,
   симулятор `connected`.

Если там `fake`, вы запустили мост с `--source fake`. Если `disconnected` — MSFS ещё грузит полёт:
мост сам повторяет попытки (1, 2, 4, 8, 16, 30 с).

### 1.5. Живые данные

Приложение → **Настройки → «Живые данные и события» → «Живые данные» = вкл**.

Без живых данных:
- не скачается `runways.csv` из OurAirports, а без него нет координат ВПП, значит не будет ни дыма, ни
  машин;
- не будет METAR назначения, а без ветра сценарий пожара не запустится.

## Часть 2. Дым: эффект и пакет

### 2.1. Убедиться, что эффекты вообще работают

Цель — исключить проблемы самого SDK, прежде чем что-то собирать.

1. Начните любой полёт. **Не в главном меню**: редакторы DevMode в меню не работают.
2. DevMode → **File → Open project…** → выберите `SimpleFX.xml` из примеров SDK.
3. Откроется **Project Editor**. Нажмите **Build All In Project**. Дождитесь конца сборки, в консоли не должно
   быть красных ошибок.
4. Откройте Visual Effects Editor: в Project Editor раскройте пакет `mycompany-simple-fx` → выделите
   группу **VisualEffectsLib** → в окне **Project Inspector** нажмите **Load In Editor**.
   (Меню View самого Project Editor — не то: там только Project Inspector и Undo History.)
5. В меню **View окна Visual Effects Editor** → **Template/Instance Debugger** → вкладка **Spawner**.
6. Выберите свой самолёт, затем любой **Contact Point** (например, двигатель) → **Spawn**. Самолёт удобно
   найти так: меню Camera → Developer Camera, клавиша `F5`. Те же кнопки спавна есть в Inspector, если
   выделить эффект в Visual Effects Editor.

**Должно получиться:** у самолёта идёт дым из примера.

**Если дыма нет:** дальше идти бессмысленно. Проблема в SDK или в DevMode, а не в нашем пакете. Проверьте
версию SDK (должна совпадать с версией симулятора), пересоберите пример, перезапустите MSFS.

### 2.2. Создать свой проект

Самый простой путь — не собирать эффект с нуля, а взять **копию примера SimpleFX** и переделать его дым
двигателя в столб дыма. В копии уже есть всё нужное: материал с текстурой дыма (`vfx_smoke.png`) и готовый
граф. Создание пустого эффекта через New Project / Wizard не нужно.

1. Закройте проект SimpleFX в DevMode, если он открыт.
2. Скопируйте **всю папку** `D:\MSFS 2024 SDK\Samples\DevmodeProjects\Misc\SimpleFX` в
   `C:\msfs-projects\acars-smoke` (вне репозитория). Оригинал в SDK не трогайте.
3. DevMode → **File → Open project…** → `C:\msfs-projects\acars-smoke\SimpleFX.xml`.
4. Project Editor → **Build All In Project** — сборка должна пройти, как у оригинала.

В проекте два пакета: `mycompany-simplefx-materiallib` (материал и текстура дыма) и `mycompany-simple-fx`
(сам эффект `EngineSmoke`). Переименовывать их не обязательно, но **оба** потом идут в Community.

> У копии те же внутренние идентификаторы (GUID), что у примера. Если кто-то поставит в Community и наш
> пакет, и исходный пример, они могут конфликтовать **[?]**. Когда эффект будет готов, пришлите мне его
> XML — я заменю GUID на новые, это механическая правка.

### 2.3. Собрать эффект столба дыма

#### Как устроен граф (на примере EngineSmoke)

Откройте эффект в редакторе: Project Editor → раскройте `mycompany-simple-fx` → группа **VisualEffectsLib** →
Project Inspector → **Load In Editor**. В окне Visual Effects Editor вы увидите граф узлов. Сверху вниз идёт
главная цепочка, а слева к ней подключены «вычисляющие» узлы:

```
VisualEffect (EngineSmokeSample)
   └─ Emitter            — сколько частиц и как долго выпускать
       └─ Init           — какой родилась частица: время жизни, размер, скорость
           └─ Update     — что с ней происходит дальше (в примере пусто)
               └─ Output — как выглядит: цвет и прозрачность

Скорость (Velocity в Init) = Add(
     LocalDirection(x = RandomValue −0.5…0.5, z = RandomValue −0.5…0.5),   ← случайный разлёт вбок
     GravityVector(GravityScale = −1)                                       ← вверх (гравитация наоборот)
)

Цвет (ParticleColor в Output) = Vector4(
     r = g = b = 0.2,                                   ← серый
     w (прозрачность) = BezierCurve(AgeOverLifetime)    ← 0 → 1 → 0: появляется и тает
)
```

Каждый параметр узла — это поле в **Inspector**: выделите узел мышью, справа появятся его поля. Число можно
ввести прямо в поле, а можно подать в него выход другого узла (протянуть связь мышью от выхода к входу).

Сейчас пример — маленький серый дымок: частица живёт 4 с, радиус 1 м, поднимается ~10 м/с. Нужно сделать
большой медленный тёмный столб и добавить ветер. Это четыре правки.

#### Правка 1. Emitter — бесконечный и видный издалека

Выделите узел **Emitter**, в Inspector:

| Поле | Значение | Зачем |
|---|---|---|
| `TimeEmission` | `-1` | без конца по времени; мост сам убирает объект |
| `RateType` | `Time` | частицы в секунду |
| `Rate` | `4` | 4 частицы в секунду; с временем жизни 60 с на экране ≈ 240 частиц — дёшево для FPS |
| `Capacity` | `300` | максимум частиц одновременно. По умолчанию 16 — при 4 в секунду и жизни 60 с нужно 240, иначе новые частицы не появятся и столб будет «рваный» |
| `EmitInLocalSpace` | **выкл** | скорость в мировых осях: «вверх» — это вверх, ветер — по сторонам света |
| `MaxDistanceEmission` | `80000` | дальше этого расстояния от камеры (в метрах) частицы не рождаются. Объект создаётся за 40 NM ≈ 74 км, поэтому 80 км. Есть ли у поля верхний предел, документация не говорит **[?]** — если дым появляется только вблизи, запишите, с какого расстояния |

#### Правка 2. Init — большие медленные частицы

Выделите узел **Init**:

| Поле | Было | Стало | Зачем |
|---|---|---|---|
| `Lifetime` (секунды) | 4 | `60` | частица успевает подняться высоко |
| `Size` (радиус, метры) | 1 | `25` | ширина клуба ~50 м |

Высота столба ≈ скорость подъёма × время жизни. Дальше подъём ~5 м/с, значит ~300 м.

#### Правка 3. Скорость: вверх медленнее, вбок шире, плюс ветер

1. Узел **GravityVector**: `GravityScale` `−1` → **`−0.5`**. Гравитация ≈ 9.8 м/с, так что подъём будет ≈ 5 м/с.
2. Два узла **RandomValue** (разлёт вбок): `MinRandValue` `−0.5` → **`−2`**, `MaxRandValue` `0.5` → **`2`**.
   Клубы расходятся шире, столб у основания толще.
3. **Ветер.** Нужно прибавить к скорости частицы скорость ветра. У ветра единицы — футы в секунду, у скорости
   частицы — метры в секунду, поэтому ветер надо умножить на 0.3048.
   1. Правый клик на пустом месте графа → в поиске `wind` → добавьте **WindDirection**. В Inspector:
      опция **`Raw`** (вектор ветра со скоростью, ft/s).
   2. Правый клик → добавьте **Multiply** (входы `x`, `y`). Тяните мышью **от** жёлтой точки `OutputValue`
      узла WindDirection **к** кружку слева от `x` у Multiply.
      Во вход `y` — узел **Vector3** с `x = y = z = 0.3048`. **Не** вписывайте 0.3048 числом прямо в `y`:
      по документации число при умножении на вектор превращается в `(0.3048, 1, 1)`, и уменьшится только
      одна ось ветра.
   3. Правый клик → добавьте второй **Add**. Первый вход — выход **старого Add** (тот, что сейчас идёт в
      `Velocity`), второй вход — выход **Multiply**.
   4. Выход **нового Add** подключите к полю **`Velocity`** узла **Init** (вместо старого Add).

   Получится: `Velocity = (разлёт вбок + подъём) + ветер × 0.3048`.

   Что ожидать: при ветре 12 узлов (≈ 6 м/с) и подъёме 5 м/с дым наклонится примерно на 50° от вертикали.
   Если наклон кажется слишком сильным, замените `0.3048` на меньшее число (например, `0.15`) — это игровая
   настройка, не физика.

Почему ветер добавляем в **Init**, а не в **Update**: в Init скорость задаётся один раз при рождении частицы,
и она летит ровно. Как работает добавление скорости в Update, документация не описывает **[?]** — можно
попробовать, если в Init результат не понравится.

#### Правка 4. Цвет — тёмный дым

Узел **Vector4** (цвет): `x`, `y`, `z` `0.2` → **`0.08`** (почти чёрный). Вход `w` (прозрачность, кривая
0 → 1 → 0) не трогайте: благодаря ей клубы плавно появляются и тают.

Если дым слишком плотный и закрывает ВПП полностью — ограничьте прозрачность: добавьте **Multiply** между
BezierCurve и `w` с числом `0.6`.

#### Сохранить и собрать

1. Visual Effects Editor → **File → Save**.
2. Project Editor → **Build All In Project**. В консоли — `0 failed`.
3. Переходите к проверке (2.4).

**Если что-то в окне называется не так**, как здесь (например, поле или узел), пришлите скриншот графа и
Inspector — разберу по нему.

### 2.4. Проверить эффект на своём самолёте

1. Сохраните эффект: Visual Effects Editor → **File → Save**.
2. **Build All In Project**.
3. Как в шаге 2.1: Visual Effects Editor → View → Template/Instance Debugger → Spawner → свой самолёт → Spawn
   (эффект `EngineSmokeSample`).
4. Поставьте ветер: панель погоды MSFS → пресет или ручная настройка, ветер 15–25 узлов.
5. Облетите самолёт камерой (drone camera).

**Должно получиться:** столб наклонён **по ветру**, то есть уходит в сторону, **противоположную** той, откуда
дует ветер. Ветер 270° (с запада) → дым уходит на восток.

**Если дым вертикальный:** `WindDirection` не подключён или подключён к узлу, который не влияет на
движение частиц. Вернитесь к шагу 2.3.

**Если дым наклонён против ветра:** вектор надо развернуть (умножить на −1) перед подачей в частицы.

### 2.5. Записать InstanceID эффекта

Это идентификатор вида `{XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX}`. По нему объект `ACARS Smoke` находит
эффект. Где взять (любой из способов):

- Visual Effects Editor → View → Template/Instance Debugger → вкладка **Asset Packages** → ваш эффект;
- или откройте `PackageSources\VisualEffectLibs\MyCompany\simple-fx\EngineSmoke.xml` в блокноте и найдите
  атрибут `InstanceId` у элемента `<VisualEffect.VisualEffect>`. В копии примера это
  `{88CDD86E-643D-4026-9A17-4E18755E5566}`, пока я не заменю GUID (шаг 2.2).

Скопируйте его целиком, с фигурными скобками.

### 2.6. Добавить объект ACARS Smoke

Объект — это «самолёт» без модели (один пустой узел без геометрии), который ничего не делает, только запускает
эффект в своей точке. Его файлы уже есть в репозитории.

1. Скопируйте из репозитория папку
   `bridge\msfs\package\PackageSources\SimObjects\`
   в `PackageSources` вашего проекта (`C:\msfs-projects\acars-smoke\PackageSources\`), **рядом** с папкой
   эффекта, которую создал редактор.
2. Файл `bridge\msfs\package\PackageSources\VisualEffectLibs\ACARS\acars_smoke.vfxlib` **не копируйте**:
   редактор уже создал свой `.vfxlib` с настоящим эффектом.
3. В **скопированном** файле
   `PackageSources\SimObjects\Airplanes\ACARS_Smoke\model\ACARS_Smoke.xml`
   найдите строку с `<FX_GUID>` и замените нули
   `{00000000-0000-0000-0000-000000000000}`
   на InstanceID из шага 2.5.
4. Проверьте в том же каталоге `aircraft.cfg`: строка `title = "ACARS Smoke"`. **Не меняйте** её: именно это
   название ищет мост.

### 2.7. Собрать пакет

1. В Project Editor выберите пакет `mycompany-simple-fx` и добавьте в него **вторую группу ассетов** (Asset Group)
   для объекта.
2. Исходная папка группы — `PackageSources\SimObjects\Airplanes\ACARS_Smoke`.
3. Тип группы: для немодульного `aircraft.cfg` в MSFS 2024 он не проверен **[?]**. Выберите из списка тип,
   подходящий для SimObject / Aircraft. **Запишите, какой выбрали**.
4. **Build All In Project**.
5. Смотрите в консоль DevMode. Возможные ошибки:
   - ошибки glTF: модель — один пустой узел, написанный вручную (первая версия с треугольником не собиралась); если сборщику она не нравится,
     **скопируйте текст ошибки дословно**;
   - ошибки `aircraft.cfg` или `model.cfg`: тоже дословно.
6. Готовые пакеты появятся в папке `Packages` рядом с файлом проекта: `mycompany-simple-fx` и
   `mycompany-simplefx-materiallib`.

### 2.8. Установить пакет

1. Найдите папку **Community**:
   - Options → General Options → Developers — там указан путь к Community; или
   - файл `UserCfg.opt`, строка `InstalledPackagesPath` — к этому пути добавьте `\Community`.
2. Скопируйте туда **обе** папки из шага 2.7 (эффект и материал).
3. **Перезапустите MSFS** (пакеты из Community читаются только при старте).

### 2.9. Проверить, что MSFS видит объект

Любым из способов:

- DevMode → **Tools → Aircraft Selector** → ищите `ACARS Smoke` в списке **[?]**;
- DevMode → **Tools → SimObject Spawner** → фильтр **Packages** = `mycompany-simple-fx` → в списке **Objects** должен
  быть наш объект. Можно сразу нажать **Spawn**: объект создаётся на земле в точке камеры разработчика, и
  дым должен пойти.

**Если объекта нет:** мост тоже не сможет его создать. Возможные причины:
- пакет не в Community или MSFS не перезапущен;
- неправильный тип группы ассетов (шаг 2.7.3) — попробуйте другой;
- симулятор требует ещё что-то для «самолёта» (пресет, лётную модель). Запишите, что именно он пишет в
  консоли, и что вы добавили, чтобы объект появился. Эти изменения потом нужно вернуть в репозиторий.

**Если объект есть, но дыма нет:**
- проверьте `<FX_GUID>` (шаг 2.6.3): InstanceID должен совпадать до символа;
- Visual Effects Editor → View → Template/Instance Debugger: появился ли экземпляр эффекта, когда объект создан;
- XML объекта запускает эффект через шаблон `ASOBO_GT_FX` из `Asobo\Generic\FX.xml`. Есть ли этот шаблон в
  MSFS 2024, не проверено **[?]**. Если в консоли ошибка про `ASOBO_GT_FX` или `FX.xml`, пришлите её.

## Часть 3. Дым: проверка в полёте

### 3.1. Подготовить план полёта

Сценарий пожара сам срабатывает редко (2 % за рейс). Для проверки его запускают вручную, но **условия
сценария должны выполняться**, иначе он не стартует:

| Условие | Как обеспечить |
|---|---|
| фаза `CRUISE` или `DESCENT` | быть в воздухе после набора — в крейсере или в снижении |
| нет диверсии | не отвечать `DIVERT` в других сценариях этого рейса |
| есть ВПП назначения | в SimBrief выбрать **ВПП прилёта** (поле Arrival Runway) |
| есть запасной | в SimBrief указать **запасной аэродром** |
| ветер в METAR назначения | ветер с направлением: `27012KT` подходит, `00000KT` (штиль) и `VRB03KT` — нет |

**Советы по рейсу:**
- короткий рейс на 80–150 NM: до 40 NM лететь недолго, а крейсер всё равно будет;
- пример — EFHK–EETN (Хельсинки–Таллин), если в METAR Таллина ветер не штиль и не VRB;
- погода в MSFS — **Live**: тогда ветер в симуляторе совпадёт с ветром из METAR, который печатается в телексе,
  и можно сравнить направление сноса.

### 3.2. Порядок запуска

1. **MSFS** → полёт на стоянке аэропорта вылета.
2. **Мост:**
   ```
   bridge\msfs\src\AcarsBridge\bin\Debug\net8.0\acars-msfs-bridge.exe --verbose
   ```
   Окно не закрывать до конца проверки.
3. **Приложение** (`pnpm desktop`) → статус «Мост симулятора»: подключён, `simconnect`.
4. Загрузите OFP из SimBrief, начните рейс, сделайте логон и FLT NBR — как обычно.
5. Взлетайте.

### 3.3. Запустить пожар

1. Наберите высоту и дождитесь фазы `CRUISE` (через минуту после выхода на эшелон) или начните снижение.
2. Окно рейса → **«Нестандартное событие»** → выберите **«Пожар у ВПП назначения»** → **«Запустить сейчас»**.
3. **В ленте должно появиться:**
   - строка «Запущено вручную: dest_fire»;
   - телекс примерно такого вида:
     ```
     FIRE REPORTED NEAR RWY 08
     SMOKE DRIFTING E, WIND 270/12KT
     VIS REDUCED IN SMOKE, RESCUE ON SCENE
     PREPARE DIVERSION EFHK
     NO ESTIMATE, NEXT UPDATE 1432Z
     REPLY HOLD OR DIVERT
     ```
     Запомните румб после `SMOKE DRIFTING` — дым в симуляторе должен уходить туда же.
4. **Если сценарий не стартовал**, в ленте написано, какое условие не выполнено. Сверьтесь с таблицей 3.1.

### 3.4. Ошибки команды дыма

В ленте **не должно** быть строки «Команда симулятору smoke не выполнена». Если она есть, вот что значит
текст после двоеточия:

| Текст | Причина | Что делать |
|---|---|---|
| `no planned runway in the OFP` | в плане нет ВПП прилёта | выбрать её в SimBrief, загрузить OFP заново |
| `no coordinates for XXXX RWY nn` | ВПП нет в OurAirports или нет сети | проверить «Живые данные», интернет; записать аэропорт и ВПП |
| `unavailable sim not connected` | мост не подключён к MSFS | шаг 1.4 |

### 3.5. Ответить и подлететь

1. Ответьте на телекс **`HOLD`** или просто подождите 8 минут: `HOLD` выбирается сам.
   **Не отвечайте `DIVERT`:** дым останется, но вы улетите от него.
2. Летите к аэродрому. На **40 NM** мост создаёт объект.
3. Если создать не удалось, ошибка будет в **статусе моста** в приложении (а не в ленте сообщений):
   `simconnect exception CREATE_OBJECT_FAILED …`. Это значит, что MSFS не нашёл объект `ACARS Smoke` —
   вернитесь к шагам 2.8–2.9.
4. Посмотрите на ВПП дважды: издалека (20–30 NM) и вблизи, на подходе. Удобно с внешней камеры.

### 3.6. Что записать

Отметьте каждый пункт и допишите, что увидели:

- [ ] дым стоит у **середины плановой ВПП**, а не в стороне и не висит в воздухе;
- [ ] с какого расстояния дым заметен (NM);
- [ ] дым наклонён **по ветру**, в сторону румба из телекса (`SMOKE DRIFTING …`);
- [ ] эффект вообще играет на объекте, которым никто не управляет **[?]** (на форумах пишут по-разному);
- [ ] FPS на 20–30 NM от аэродрома: перед появлением дыма (дальше 40 NM) и с дымом. Счётчик — DevMode
      (Debug → статистика) или ваш оверлей;
- [ ] через 20 минут HOLD (или позже — время случайное, от 20 минут до 2 часов, с обновлениями каждые
      20 минут) приходит телекс `FIRE NEAR RWY … UNDER CONTROL`, и **дым исчезает**.

Чтобы не ждать до 2 часов, можно ускорить симуляцию (×2, ×4): время в сценарии полётное.

### 3.7. Проверить, что дым убирается

Каждый случай — отдельный короткий тест, можно на том же аэродроме:

1. **По сценарию** — после «UNDER CONTROL» (шаг 3.6).
2. **Удаление дальше 60 NM** — запустить пожар, подлететь ближе 40 NM (дым появился), отлететь дальше
   60 NM, вернуться: дым должен исчезнуть, а на 40 NM появиться снова. Между 40 и 60 NM ничего не меняется,
   так задумано.
3. **Остановка рейса** в приложении — дым исчезает сразу.
4. **Выход из MSFS** при живом дыме, затем новый запуск и полёт к тому же аэродрому, не останавливая рейс в
   приложении: мост создаёт дым заново, потому что запрос ещё действует (до 90 минут или до остановки
   рейса).
5. **90 минут** — после запуска пожара дым живёт не дольше 90 минут, даже если сценарий не закончился.
   Этот пункт можно не проверять специально: он под тестами.

## Часть 4. Аварийные службы: что нужно до начала работы

> **Устарело (2026-10-17):** актуальный гайд по аварийным службам — `docs/guide-rescue.ru.md`.

Задача T54 одобрена (своя реализация в мосте), но в карточке есть места, которые нельзя угадывать. Код я
начну, когда они будут закрыты.

### 4.0. Уже проверено мной (2026-10-15) — от вас ничего не нужно

| Что | Результат |
|---|---|
| ВПП посадки из OFP | поле SimBrief `destination.plan_rwy` есть во всех наших OFP (например, RJBB `06L`), ядро его уже разбирает (`ofp/parse.ts`, `planRwy`) |
| Движение машин | структура `SIMCONNECT_DATA_WAYPOINT` есть в вашей обёртке SimConnect (`SimConnectLibs/sdk2024/…/Microsoft.FlightSimulator.SimConnect.dll`), так что маршрут машин через `AI WAYPOINT LIST` собрать можно. Работает ли это в симуляторе, покажет проверка после реализации |
| SimObject Spawner | в MSFS 2024 есть: DevMode → Tools → SimObject Spawner (документация SDK) |

### 4.1. Шаг 1 — найти названия машин (обязательно, только вы)

Мост создаёт машину по её **названию** (`title` в `sim.cfg` / `aircraft.cfg` объекта). Названия по умолчанию
взяты из настроек мода Emergency Response On Demand. Есть ли такие объекты в вашем MSFS, неизвестно.

**Проверяем вот эти пять:**

| № | Название | Ожидается |
|---|---|---|
| 1 | `ASO_Firetruck02` | пожарная машина |
| 2 | `Truck Fire Long 02` | пожарная машина (длинная) |
| 3 | `Truck Fire Short` | пожарная машина (короткая) |
| 4 | `Truck Fire Short 02` | пожарная машина (короткая) |
| 5 | `SUV_NorthAm` | внедорожник руководителя тушения |

**Как проверить:**

1. MSFS 2024, любой полёт **на земле** в крупном аэропорту (например, EDDF), Developer Mode включён.
2. DevMode → **Tools → SimObject Spawner**.
3. Фильтр **Packages** — «All Packages».
4. Откройте список **Objects** и ищите каждое название из таблицы. Если в списке можно вводить текст, вводите
   часть названия: `Fire`, `Truck`, `SUV` **[?]**.
5. Снимите галку **Lock Position** и переведите камеру разработчика (Developer Camera, где она включается
   в 2024 — **[?]**) на перрон рядом с собой. Галка **Display Position Debug** показывает сферу в точке, где
   появится объект: точка спавна всегда на земле.
6. Выберите объект → **Spawn**.
7. Для каждого запишите:
   - найден ли в списке и под каким **точным** именем (большие/маленькие буквы, пробелы, подчёркивания);
   - появился ли на земле (не под землёй, не в воздухе);
   - как выглядит: пожарная машина, какой окраски, SUV;
   - есть ли мигалки (Play Animation, если кнопка есть).
8. Удалите созданные объекты кнопкой **Remove All** внизу окна.

**Если названия в списке Objects отличаются от таблицы** (например, показано имя папки, а не `title`):
DevMode → **Tools → Virtual File System** → найдите папку объекта (поиск по `fire`, `truck`) → откройте
`sim.cfg` или `aircraft.cfg` → строки `title = …`. Запишите именно их: мост использует `title`.

**Если в списке есть ещё пожарные машины** (другие модели, аэродромные машины с пеной, Rosenbauer Panther и
т. п.) — запишите их тоже. Чем больше разных моделей, тем лучше выглядит колонна.

### 4.2. Шаг 2 — найти скорую

В настройках мода скорой нет, её надо найти.

1. Там же, в SimObject Spawner, ищите по словам: `ambulance`, `medic`, `EMS`, `rescue`, `paramedic`,
   `hospital`.
2. Если ничего: Tools → Virtual File System, тот же поиск по именам папок.
3. Нашли — заспавните, проверьте, что это действительно скорая, запишите точный `title`.
4. Не нашли — напишите «скорой нет». Тогда уровень `medical` будет давать только сообщение в ленте, без
   машины (так одобрено в карточке). Позже можно будет добавить название в настройках приложения, если
   найдёте её в каком-то аддоне.

### 4.3. Шаг 3 — MSFS 2020 (если есть)

Если у вас установлен MSFS 2020, повторите шаги 4.1–4.2 там. В 2020 SimObject Spawner нет **[?]**, ищите
через Aircraft Selector или Virtual File System.

Если MSFS 2020 нет — так и напишите: тогда в отчёте T54 будет «в 2020 не проверено».

### 4.4. Шаг 4 — выбрать источник для числа машин

Сколько пожарных машин ставить, зависит от **категории аэродрома по пожарно-спасательной защите**. Её
определяет самый большой самолёт (длина и ширина фюзеляжа) — ICAO Annex 14, том I, таблица 9-1. Число машин
по категории — Annex 14 / Doc 9137, часть 1.

Сейчас в карточке такая таблица:

| Категория | Типичные самолёты (ориентир) | Машин |
|---|---|---|
| 1–5 | малые, региональные | 1 |
| 6–7 | A320, B737 | 2 |
| 8–10 | A330, B777, A350, A380 | 3 |

Плюс один SUV руководителя тушения.

Но она взята из **вторичного источника** (презентация KCAA на ICAO ESAF 2022 со ссылкой на Doc 9137).
Annex 14 и Doc 9137 платные, в открытом доступе их нет. По правилу реализма нужно ваше решение — выберите
**один** вариант:

- **а) Первоисточник.** У вас есть Annex 14 том I или Doc 9137 часть 1 (PDF) — пришлите файл или путь к нему.
  Я сверю таблицу и запишу источник с датой сверки.
- **б) Вторичный источник как допущение.** Таблица остаётся как выше, в карточку записывается «по презентации
  KCAA / ICAO ESAF 2022, не по первоисточнику».
- **в) Игровое правило.** Без ссылки на ICAO, например: узкофюзеляжный — 2 машины, широкофюзеляжный — 3,
  региональный — 1.

### 4.5. Шаг 5 — пройти проверку дыма

Части 2–3 этого гайда пройдены, и `ACARS Smoke` создаётся мостом **без** `CREATE_OBJECT_FAILED`.

Это не формальность: машины создаются тем же вызовом `AICreateSimulatedObject`. Если он не работает для
дыма, машины тоже не появятся, и сначала нужно разобраться с ним.

Если дым целиком не получается (например, застряли на эффекте), но объект `ACARS Smoke` создаётся (виден в
SimObject Spawner и нет ошибки в статусе моста) — этого достаточно, чтобы начинать T54.

## Часть 5. Аварийные службы: запуск задачи и проверка

### 5.1. Запустить задачу

Когда шаги 4.1–4.5 готовы, начните новую сессию и напишите:

> Сделай T54. Названия пожарных машин: <список из 4.1, точные title>. SUV: <title или «нет»>.
> Скорая: <title или «нет»>. MSFS 2020: <результат 4.3 или «нет»>. Таблица категорий: вариант <а/б/в>.
> Дым проверен: <да / объект создаётся, эффект не готов>.

Что я сделаю по карточке:

1. **Ядро и сценарии.** Шаг сценария `rescue: full | standby | medical` и `rescue: stop`. Подключу его к
   сценариям:
   - `emergency_mayday`, `ped_fire_cabin` → `full` (машины ждут у ВПП, едут за самолётом, окружают);
   - `emergency_pan` → `standby` (машины стоят на позициях, не едут);
   - `medical_onboard`, команда `MEDICAL` → `medical` (скорая у стоянки после on-block);
   - если сначала PAN, потом MAYDAY — действует старший уровень.
2. **Приложение.** Порог и курс ВПП посадки из OurAirports (плановая из OFP, иначе самая длинная; при
   диверсии — аэропорт диверсии), команда мосту `rescue_start`, настройки:
   - «Аварийные службы в симуляторе» — вкл/выкл;
   - списки названий объектов (пожарные, скорая) — можно редактировать;
   - сирена — звук на ПК, по умолчанию выключена.
3. **Мост.** `RescueController` с тестами (как `SmokeController`): появление на 15 NM, следование,
   окружение, удаление через 10 минут, на 30 NM и при выходе из MSFS, повторное создание в новой сессии.
4. Отчёт с разделом «Проверка человеком».

### 5.2. Проверка после реализации

Условия: MSFS 2024, FBW A32NX (или любой A320), рейс с ВПП прилёта в SimBrief, живые данные включены,
настройка «Аварийные службы в симуляторе» включена, станция УВД ROPS включена.

**Тест A — MAYDAY (уровень full):**

1. Логон на ROPS (станция `X` + код FIR), в крейсере отправьте MAYDAY, на вопрос ответьте `CONTINUE`
   (продолжать до назначения).
2. Подлетайте. На **15 NM** у порога ВПП посадки должны появиться пожарные машины (для A320 — 2, если
   оставили таблицу а/б) и SUV — сбоку от ВПП, примерно в 45 м от оси.
3. После **касания** машины едут за самолётом, держась примерно в 25 м позади.
4. После **остановки** (меньше 1 узла дольше 2 секунд) окружают самолёт по кругу радиусом около 50 м.
5. Через **10 минут** после остановки исчезают.
6. FPS: запишите значение до 15 NM и с машинами.

**Тест B — PAN (уровень standby):**
то же, но с PAN. Машины стоят на позициях у ВПП и **не едут** за самолётом.

**Тест C — уход на второй круг:**
MAYDAY, машины появились, уходите на второй круг и отлетите дальше 30 NM — машины должны исчезнуть. Вернитесь
ближе 15 NM — появятся снова.

**Тест D — MEDICAL (уровень medical):**
команда `MEDICAL` в полёте, посадка, заруливание, on-block. Если скорая найдена (шаг 4.2) — она у стоянки.
Если нет — только сообщение в ленте.

**Тест E — посадка на другую ВПП:**
MAYDAY, садитесь не на плановую ВПП. Машины стоят у плановой, после касания едут к месту остановки самолёта
(по прямой).

**Тест F — MSFS 2020** (если есть): повторить тест A кратко.

**Что считается нормальным** (это одобренные упрощения, не ошибки):
- машины едут **по прямой**, по траве и сквозь здания, а не по рулёжкам;
- машины стоят у ВПП **заранее**, а не выезжают из пожарного депо;
- сирена звучит из колонок ПК, а не из машины в 3D;
- пороги 15 / 30 NM и 10 минут — игровые числа.

**Что записать:** по каждому тесту — что появилось, где, сколько, как двигалось, сколько держалось, FPS,
дословные ошибки (лента и статус моста), скриншоты.

## Приложение. Частые проблемы

| Симптом | Причина | Где смотреть |
|---|---|---|
| В выводе сборки моста `SimConnect support OFF` | не найден SDK | шаг 1.3, `-p:MsfsSdk=…` или `Local.props` |
| Статус моста `fake` | мост запущен с `--source fake` | запустить без флага |
| Статус моста `disconnected` | MSFS ещё грузит полёт или закрыт | подождать, мост переподключится сам |
| Сценарий пожара не стартует | не выполнено условие | строка в ленте; таблица 3.1 |
| `no coordinates for … RWY …` | нет живых данных или ВПП нет в OurAirports | шаг 1.5; записать аэропорт |
| `ACARS Smoke` нет в Aircraft Selector / Spawner | пакет не в Community, не собран или неверный тип группы | шаги 2.7–2.9 |
| `CREATE_OBJECT_FAILED` в статусе моста | MSFS не нашёл объект с `title = "ACARS Smoke"` | шаги 2.8–2.9 |
| Объект создан, ошибок нет, дыма нет | неверный `FX_GUID` или нет шаблона `ASOBO_GT_FX` | шаг 2.6.3; Template/Instance Debugger (меню View окна Visual Effects Editor) |
| Дым под землёй или в воздухе | как MSFS считает высоту при `OnGround = 1` **[?]** | записать, на какой высоте он стоит |
| Дым вертикальный при сильном ветре | в эффекте нет `WindDirection` | шаг 2.3 |
| Дым наклонён против ветра | вектор ветра не развёрнут | шаг 2.4 |
| MSFS вылетает при остановке эффекта в Template/Instance Debugger | замечено 2026-10-15 (MSFS 1.9.18, моды графики отключены, ошибка 0xC0000005 в самом `FlightSimulator2024.exe`) **[?]** | эффект не останавливать, а заканчивать полёт; при проверке 3.7 записать, вылетает ли MSFS, когда мост удаляет дым |
| Сильно падает FPS | слишком много частиц в эффекте | уменьшить число частиц, увеличить их размер |
| Машина не появляется (после T54) | неверный `title` | шаг 4.1, Virtual File System → `title` |
