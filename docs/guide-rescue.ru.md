# Аварийные службы в симуляторе: как добавить

Пошаговый гайд для задачи **T54**: при аварийной ситуации аэродром посадки встречает самолёт пожарными
машинами и скорой. Здесь описано, что нужно сделать **вам** (в MSFS это можете проверить только вы), что потом
сделаю я и как проверить результат. Отдельно описано, как позже добавить свои машины, например из аддона.

Состояние на 2026-10-17: машины найдены (часть 2), правила выбраны (часть 3), осталось запустить T54 (часть 4).
Карточка — T54 в `docs/07-roadmap-tasks.md`, решения и допущения записаны там.
Этот гайд заменяет части 4–5 файла `docs/guide-smoke-rescue.ru.md`.

Пометка **[?]** значит, что в документации SDK этого нет или это никто не проверял. Запишите, что вы увидели
на самом деле. Это и есть результат.

## Часть 0. Как это будет работать

```
сценарий: MAYDAY / PAN / пожар в кабине / медицина
   │  шаг «rescue: full | standby | medical»
   ▼
ядро: аэропорт посадки (диверсия, иначе назначение из OFP) + уровень
   ▼
приложение (controller.ts)
   │  порог и курс ВПП посадки из OurAirports (плановая из OFP, иначе самая длинная)
   │  число машин по самолёту + названия объектов из настроек
   │  rescue_start {level, rwy, count, titles}
   ▼
мост (RescueController, ws://127.0.0.1:47830)
   ≤ 15 NM  → машины появляются сбоку от ВПП (45 м от оси), расставлены по всей её длине
   касание  → едут за самолётом, 25 м позади (только full)
   стоп     → окружают самолёт по кругу радиусом 50 м
   +10 мин  → исчезают; дальше 30 NM (уход на второй круг) — тоже
   ▼
MSFS: стандартные машины (объекты SimObject), созданные через AICreateSimulatedObject
```

Какие сценарии что вызывают (одобрено 2026-10-15):

| Сценарий | Уровень | Что происходит |
|---|---|---|
| `emergency_mayday`, `ped_fire_cabin` | `full` | машины ждут у ВПП, едут за самолётом, окружают |
| `emergency_pan` | `standby` | машины стоят у ВПП и не едут |
| `medical_onboard`, команда `MEDICAL` | `medical` | скорая у стоянки после on-block |
| PAN, затем MAYDAY | старший уровень | `standby` → `full` |

Главное: **свой пакет для машин делать не нужно**, в отличие от дыма. Мост создаёт уже установленные в MSFS
объекты по их **названию** (`title`). Если названия нет или объект не создаётся, машины не появятся. Поэтому
ваша основная работа — часть 2.

## Часть 1. Что уже готово

От вас здесь ничего не нужно, это для понимания.

| Что | Состояние |
|---|---|
| Мост с SimConnect, Developer Mode, SDK | настроено для дыма (`guide-smoke-rescue.ru.md`, часть 1) |
| Создание объектов мостом | работает: дым `ACARS Smoke` создаётся обычным `AICreateSimulatedObject`, проверено человеком 2026-10-16/17 (LEBL) |
| ВПП посадки из OFP | поле SimBrief `destination.plan_rwy` есть, ядро его разбирает (`planRwy`) |
| Маршрут для движения машин | структура `SIMCONNECT_DATA_WAYPOINT` есть в вашей обёртке SimConnect (`SimConnectLibs/sdk2024`) |
| Сценарии MAYDAY / PAN / медицина | есть, сообщения уже пишут «RESCUE AND FIRE SERVICES ALERTED», но машин пока нет |
| Код T54 (`rescue`, `RescueController`, настройки) | написан 2026-10-17 (ветка `task/T54-rescue`), ждёт проверки (часть 5) |

Что мы узнали на дыме и что важно для машин:

1. **Объект в списке SimObject Spawner — ещё не значит, что он создаётся.** Первый вариант дыма (`aircraft.cfg`)
   был в списке, но не появлялся. Поэтому машины нужно **заспавнить**, а не только найти в списке.
2. **Обычный `AICreateSimulatedObject` работает только с немодульными объектами** (SDK). Варианта `_EX1` в вашей
   обёртке нет. Если машина в MSFS 2024 сделана модульной, мост её не создаст **[?]**.
3. Первый объект сессии у дыма создавался без эффекта, поэтому мост пересоздаёт его через 15 с. У машин эффекта
   нет, так что это, скорее всего, не нужно **[?]**. Проверим в части 5 (мигалки).

## Часть 2. Машины в MSFS: найдено

Проверено вами 2026-10-17 в MSFS 2024 (DevMode → Tools → SimObject Spawner, фильтр «All packages», поиск по
`fire`, `medic`, `pickup`). Все объекты ниже создаются кнопкой **Spawn** и стоят на земле.

### 2.1. Пожарные машины

| title | Что это |
|---|---|
| `ASO_Firetruck02` | аэродромная, белая, 4 оси |
| `Truck Fire Airport Medium` | аэродромная, салатовая |
| `Microsoft_Truck_Fire_Medium_Red` | аэродромная, красная, с анимацией; **едет задом наперёд** (проверка 2026-10-17), убрана из списков по умолчанию |
| `FSDT_Firetruck_Panther_6x6_red` | Rosenbauer Panther из GSX (аддон), с анимацией |
| `Truck Fire Long 02` | городская с лестницей (США) |
| `Microsoft_Truck_Fire_Long` | городская с лестницей, с анимацией |
| `Truck Fire Short` | городская, европейская |
| `Car Bush Firefighting` | внедорожник (не используется: машины руководителя нет) |

`SUV_NorthAm` из настроек мода ERoD в MSFS 2024 нет. `Truck Fire Short 02` не подтверждена.

### 2.2. Скорые

| title | Что это |
|---|---|
| `Car Bush Medic` | внедорожник |
| `Truck Utility Europe Medic Box` | европейский фургон с кузовом-коробкой |
| `Truck Utility Europe Medic Flush` | европейский фургон |
| `Truck Utility NorthAm Medic` | американская, кузов-коробка |
| `Van Asia High Roof Medic` | азиатский фургон с высокой крышей |
| `Van Asia High Roof Medic Japan` | японская |
| `Van Asia Low Roof Medic` | азиатский фургон с низкой крышей (найден в списке, не спавнился) |

### 2.3. Скобки в названиях — это ливреи

В списке Spawner есть строки вида `Pickup 01 (FIREFIGHT_01)`. Скобки — это **ливрея**, а не часть `title`:
у `Pickup 01` один контейнер и шесть окрасок (`AERIALAD_02`, `FIREFIGHT_01`, `TRAFFIC_DEFAULT` и др.). Так в
MSFS 2024 выглядят **модульные** объекты.

Ливрею можно передать только в `AICreateSimulatedObject_EX1` (параметр `szLivery`, SDK 2024). В нашей обёртке
SimConnect этой функции нет, поэтому мост создаёт машину по названию **без скобок**, с ливреей по умолчанию.
Все машины из таблиц выше без скобок выглядят правильно. Не подходят:
- `Pickup 01` — без скобок служебный, сине-красный, а не пожарный;
- жёлтая ливрея `ASO_Firetruck02` — без `_EX1` останется белая.

Создаёт ли обычный `AICreateSimulatedObject` модульные машины, проверится в части 5 **[?]**. Мод ERoD создаёт
`ASO_Firetruck02` тем же вызовом, так что, скорее всего, да. Если нет, нужна официальная обёртка SimConnect
с `_EX1` (задача T19).

MSFS 2020 у вас нет: в отчёте T54 будет «в 2020 не проверено».

## Часть 3. Какие и сколько машин: решено

Все правила ниже — **игровые** (решения пользователя 2026-10-17), а не нормативы ICAO или данные о реальных
службах аэропортов. Записаны в карточке T54.

**Сколько пожарных машин** — по категории самолёта:

| Категория | Самолёты | Пожарных машин |
|---|---|---|
| 1–5 | малые, региональные (E170/E175, CRJ, ATR, DH8 до Q400), тип не из таблицы | 1 |
| 6–7 | A320, B737, E190, E195, DH8D | 4 |
| 8–10 | A330, B777, A350, A380 | 8 |

Машины руководителя тушения нет.

ВПП без плановой (диверсия) — самая длинная; посадка против ветра из METAR аэропорта, без ветра — на конец `le`
(решения пользователя 2026-10-17, записаны в карточке).

**Какие пожарные машины** — по аэропорту посадки. Крупный аэропорт — `type = large_airport` в OurAirports
(`airports.csv`), регион — по первым буквам кода ICAO.

| Аэропорт | Пожарные машины |
|---|---|
| крупный, Северная Америка (`K`, `C`) | `Truck Fire Airport Medium` |
| крупный, остальные регионы | `ASO_Firetruck02`, `Truck Fire Airport Medium` |
| не крупный, Северная Америка | `Truck Fire Long 02`, `Microsoft_Truck_Fire_Long` |
| не крупный, остальные регионы | `Truck Fire Short` |

**Какая скорая** — по региону:

| Регион (ICAO) | Скорая |
|---|---|
| Япония (`RJ`, `RO`) | `Van Asia High Roof Medic Japan` |
| остальная Азия (`R`, `V`, `W`, `Z`) | `Van Asia High Roof Medic`, `Van Asia Low Roof Medic` |
| Северная Америка (`K`, `C`) | `Truck Utility NorthAm Medic` |
| Европа (`E`, `L`) и остальные | `Truck Utility Europe Medic Box`, `Truck Utility Europe Medic Flush` |

Если в группе моделей меньше, чем нужно машин, они чередуются по кругу. Все группы можно редактировать в
настройках. `FSDT_Firetruck_Panther_6x6_red` (GSX) по умолчанию не включается, его можно добавить вручную.

## Часть 4. Запустить задачу

Всё, что нужно было от вас до начала, собрано. Начните **новую сессию** и напишите:

> Сделай T54.

Названия машин и правила уже в карточке. Что я сделаю по ней:

1. **Ядро и сценарии.** Шаги `rescue: { level: full | standby | medical }` и `rescue: stop`; подключение к
   сценариям из таблицы части 0; старший уровень при PAN → MAYDAY; запись в replay (как `smoke`).
2. **Приложение.** Порог и курс ВПП посадки (OurAirports, плановая из OFP, иначе самая длинная; при диверсии —
   аэропорт диверсии), команда мосту `rescue_start`, число и модели машин по части 3, настройки:
   - «Аварийные службы в симуляторе» — вкл/выкл;
   - группы названий объектов (пожарные и скорые по аэропорту) — редактируемые;
   - сирена — звук на ПК, по умолчанию выключена.
3. **Мост.** `RescueController` (логика без SimConnect, под тестами, как `SmokeController`) и команды
   `rescue_start` / `rescue_stop` в белом списке.
4. `pnpm check`, `pnpm bridge:test`, отчёт с разделом «Проверка человеком».

Ветка — `task/T54-rescue`. Коммит — после зелёных проверок, push и merge — только по вашей просьбе.

## Часть 5. Проверка после реализации

**Условия:** MSFS 2024, FBW A32NX (или любой A320), рейс SimBrief с ВПП прилёта, мост собран с SimConnect
(`pnpm bridge:build -p:MsfsSdk=…`), живые данные и станция УВД ROPS включены, настройка «Аварийные службы
в симуляторе» включена.

**Тест A — MAYDAY (full).**
1. Логон на ROPS (`X` + код FIR), в крейсере MAYDAY, на вопрос ответ `CONTINUE`.
2. На **15 NM** у порога ВПП посадки появляются пожарные машины — для A320 четыре, модели по
   аэропорту (часть 3) — сбоку от ВПП, примерно в 45 м от оси. Окраска — по умолчанию, как в Spawner без скобок.
3. После **касания** машины едут за самолётом, примерно в 25 м позади.
4. После **остановки** (меньше 1 узла дольше 2 с) окружают самолёт по кругу радиусом около 50 м.
5. Через **10 минут** после остановки исчезают.
6. FPS — до 15 NM и с машинами.
7. Сразу после появления машины **стоят** и не катятся (до исправления 2026-10-17 они сами медленно уезжали).
   Запишите, куда смотрит каждая модель: к полосе или от неё.
8. На круге машины останавливаются и стоят до исчезновения.
9. В консоли моста — строки `rescue slot N <название> hdg asked X, sim Y`: перепишите их (видно, держит ли курс каждая модель).
10. После касания машины едут **передом**; к точке на другой стороне самолёта — **в объезд**, не сквозь самолёт.

**Тест B — PAN (standby).** То же с PAN: машины стоят у ВПП и **не едут**.

**Тест C — уход на второй круг.** MAYDAY, машины появились → уход на второй круг дальше 30 NM → исчезают.
Снова ближе 15 NM → появляются.

**Тест D — MEDICAL.** Команда `MEDICAL` в полёте, посадка, on-block. Скорая у стоянки, модель по региону (часть 3).
Например, в Европе — `Truck Utility Europe Medic Box` или `Flush`, в Японии — `Van Asia High Roof Medic Japan`.

**Тест D2 — регион и размер аэропорта.** Тест A в крупном аэропорту США (например, KJFK) — салатовые
`Truck Fire Airport Medium`; в небольшом европейском — `Truck Fire Short`.

**Тест E — другая ВПП.** MAYDAY, посадка не на плановую ВПП. Машины стоят у плановой, после касания едут к месту
остановки по прямой.

**Тест F — новая сессия.** Машины стоят → выйдите в меню MSFS и загрузите полёт снова (запрос ещё активен) →
машины созданы заново.

**Это нормально** (одобренные упрощения, не ошибки):
- машины едут **по прямой**, по траве и сквозь здания, а не по рулёжкам;
- машины стоят у ВПП **заранее**, а не выезжают из депо;
- сирена звучит из колонок ПК, а не из машины;
- 15 / 30 NM и 10 минут — игровые числа.

**Что записать:** по каждому тесту — что появилось, где, сколько, как двигалось, сколько держалось, есть ли
мигалки, FPS, дословные ошибки (лента и статус моста), скриншоты.

## Часть 6. Как добавить свою машину позже

Работает **после T54**: названия машин будут в настройках приложения.

1. **Установите аддон** с машиной в `Community` (или найдите объект в штатных пакетах).
2. **Найдите название:** DevMode → Tools → SimObject Spawner → «All packages» → второй выпадающий список, поиск
   по части имени. Нужна строка **без скобок**: в скобках — ливрея (часть 2.3).
3. **Заспавните строку без скобок** и посмотрите на окраску. Именно так машина появится у ВПП: ливрею наш мост
   выбрать не может. Не появилась или окраска не та — машина не подходит.
4. Если название в Spawner обрезано, его можно прочитать в файле: Tools → Virtual File System → **Browse**
   (фильтр **Files**, **Recursive**, поиск по имени) — путь к `sim.cfg` / `aircraft.cfg`; открыть файл —
   через **VFS Projector** (Start → Open Explorer → `VFSProjection`), строка `title = …`. Файлы с замком 🔒
   не открываются. У аддона в Community файл просто лежит на диске.
5. **Впишите `title`** в настройках приложения: «Аварийные службы» → список пожарных машин или скорой. Точно,
   с регистром и пробелами. Порядок в списке — порядок машин: первая модель — у машины ближе всех к порогу
   (и первой в колонне), дальше по кругу. У скорой берётся первая модель группы.
6. **Проверьте** тестом A из части 5. Не появилась — в ленте будет строка с названием и ошибкой, остальные
   машины работают.

Лицензия: аддон с машиной ставит каждый пользователь сам, мы его не распространяем. В репозиторий и настройки
по умолчанию попадают только названия штатных объектов MSFS.

## Приложение. Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| Машина есть в списке Spawner, но после Spawn не появляется | контейнер не создаётся (так было с первым дымом) или объект модульный | записать путь и `category`; искать другую модель |
| Машина под землёй или в воздухе | как MSFS ставит высоту при `OnGround = 1` **[?]** | записать, на какой высоте стоит |
| Машина не появляется (после T54) | неверный `title` | Virtual File System → `title`, исправить в настройках |
| Машины нет, в статусе моста `CREATE_OBJECT_FAILED` | MSFS не нашёл объект с таким `title` | то же |
| Статус моста `SimConnect support OFF` | мост собран без SDK | `pnpm bridge:build -p:MsfsSdk="C:\MSFS 2024 SDK"` |
| Машины не появились на 15 NM | нет координат ВПП (живые данные выключены или ВПП нет в OurAirports) | строка в ленте; включить живые данные |
| Машины стоят, но не едут после касания при MAYDAY | уровень `standby` (PAN) или маршрут `AI WAYPOINT LIST` не работает **[?]** | проверить уровень в ленте; записать |
| Машины едут, но отстают или дёргаются | маршрут обновляется раз в 350 мс, скорость машины своя | записать, насколько отстают |
| Сильно падает FPS | много машин | записать FPS; уменьшить список в настройках |
