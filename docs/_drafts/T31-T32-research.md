# T31/T32 — исследование источников и допущений (ЧЕРНОВИК НА ОДОБРЕНИЕ)

Дата сверки: **2026-10-15**. Код не менялся, не коммитится. Правило: `07`, «Правило реализма». Пометки: ✔ — подтверждено источником; ~ — частично/из вторичного источника; ✗ — не найдено или недоступно (`[ПРОВЕРИТЬ]`).

Ограничение исследования: поиск был общий, часть страниц недоступна (airframes.io — отказ соединения, OpenSky `/data/aircraft` — 403, groups.io — 402). Первоисточники (ARINC 618/620/622, Doc 9869, ADN) закрыты платным доступом, их тексты я не читал.

## Главный вывод

1. **Открытого авторитетного списка наземных VHF-станций ACARS (SITA/ARINC/AVICOM) с координатами нет.** Реальную станцию «в прямой видимости» без допущения не выбрать.
2. **Строка `AES:… GES:… .<рег>` — это формат вывода декодера (JAERO / inmarsat-sniffer), а не то, что показывает кабина.** Пилот на CDU/MCDU такого заголовка не видит (вывод из того, что все найденные образцы — логи SDR-декодеров; ARINC-документов я не читал, помечено ~). Значит T32 — «как на лентах слушателей», а не «как в кабине».
3. Спутники (Inmarsat GEO, Iridium по TLE) — реализуемы с проверенными данными, кроме **привязки GES-кодов к наземным станциям и точных задержек**.
4. **Реальных измеренных задержек доставки VHF/SATCOM/Iridium я не нашёл.** Любые числа задержки — допущение.

**Варианты для T31 (VHF):**
- **A. Станция = аэропорт.** Берём ближайший аэропорт из уже используемых OurAirports (public domain) как «условную станцию»; название — код ICAO аэропорта. Допущение: реальные станции стоят не в каждом аэропорту и не под этими названиями.
- **B. Радиус покрытия от любого аэропорта вместо станций.** «Есть VHF», если до ближайшего аэропорта ≤ R НМ (радиогоризонт `1.23·√h` НМ для высоты в футах — стандартная формула, ✔ общеизвестная, но источник для цитирования не искал). Допущение: покрытие в реальности неоднородно (океаны, Африка, Россия частично).
- **C. Вообще не называть станцию VHF**, показывать только «VHF / SATCOM» и вид линии. Допущений меньше всего, но «станции в окне» нет.
- Реальную базу собирать самим (по squitter) — вне рамок.

## 4. Заголовки AES/GES и ICAO hex

Реальные образцы (декодеры, не документация) ~:
- `AES:4249EA GES:50 2 .VQ-BLQ !` — GES 50 = 4F1 143°E (L-Band.md).
- `TC AES:3B75A8 GES:D0 2 .F-UJCH !` — GES D0 = 4F3 98°W.
- `AES:AE07EAGES:022.50107A!` (слипшийся вариант).
- Другие: `AES:C2B3EB GES:05 2 .77703A !`, `AES:3C6503 GES:05 2 .D-AIHC !`, `AES:AA75EF GES:02 2 .N773UA` ([RadioReference](https://forums.radioreference.com/threads/acars-the-future-inmarsat.330782/page-2) и поиск).

Что известно: AES — 6 hex-цифр = 24-битный ICAO-адрес борта ✔(обычно, по нескольким образцам; у `.77703A` регистрация подменена hex — при отсутствии регистрации); GES — 2 hex-цифры код наземной станции; «2» — режим; `.XXXX` — регистрация; `!` — признак/подтверждение (интерпретация моя, **~ вывод**). Точного описания полей нет — спецификация ARINC 618/620 не читалась (✗); код JAERO (MIT) можно использовать как справку по полям.
GES-коды ↔ спутники: таблица есть только для L-band частот (43, 44, 02 → 3F5/54°W; 05, D0, 02 → 4F3/98°W; 50, 82, 85 → 4F1/143°E; 90, C5, C1 → 4A4F4/25°E) ~ любительская; GES 02 встречается у двух спутников — однозначного соответствия нет. Расположение физических станций по кодам — ✗.

ICAO hex борта:
| Источник | Лицензия | Вывод |
|---|---|---|
| Ввод в профиле самолёта | — | ✔ без допущений; единственный вариант «из коробки» |
| OpenSky aircraft database | страница недоступна (403); условия данных: некоммерческое исследование/образование, внутренние тесты, госцели; иная копия требует разрешения для коммерции ✗ | не использовать без прочтения условий `[ПРИ РЕЛИЗЕ]` |
| ADS-B Exchange basic-ac-db | явной лицензии нет; коммерческое использование — письменное разрешение; нет массовой передачи ✗ | не использовать |
| Реестры гражданской авиации (FAA и др.) | не проверял | кандидат на уточнение `[ПРОВЕРИТЬ]` |
| Алгоритмическое получение hex из регистрации | для США (N-номера→ICAO) алгоритм детерминирован и известен, для остальных стран нужны таблицы | не проверял |

Для симулятора регистрация часто не соответствует реальному борту; естественный вариант — пользователь вводит hex (или он берётся из SimBrief/OFP, если там есть — `[ПРОВЕРИТЬ]`, поле в OFP не искал).

## 5. Перенос для узких дисплеев

Реальных правил переноса строки заголовка я **не нашёл** (✗). Существующий форматтер (`docs/03-architecture.md`, T05) уже переносит по пробелу, ширина 24 (B77x 27, B78x 30). Заголовок `AES:xxxxxx GES:xx 2 .REG !` ≈ 26–33 символа и не умещается в 24. Следовательно, правило — допущение (проект). Предлагается: разбить по токенам (`AES:…` / `GES:… 2` / `.REG`), не рвать токен; если токен длиннее строки — жёсткий перенос форматтера. Заголовок идёт **до** форматтера как часть тела, ни в обход (инвариант 9).
