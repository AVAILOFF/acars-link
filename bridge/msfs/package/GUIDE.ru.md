# T34 — дым у ВПП: пошаговая проверка человеком

Краткая версия — `README.md`, «To finish». Здесь то же самое подробно, с ожидаемым результатом на каждом шаге
и с тем, что делать, если не вышло. Всё, что помечено **[?]**, в SDK не описано или не проверено: запишите,
что увидели на самом деле, это и есть результат проверки.

## Как это устроено (что проверяем)

```
dest_fire (сценарий) ──smoke: start──▶ приложение ──OurAirports runways.csv──▶ середина плановой ВПП
                                              │
                                              └─ smoke_start {lat, lon} ──▶ мост (ws://127.0.0.1:47830)
мост: самолёт ≤ 40 NM от точки ──▶ AICreateSimulatedObject("ACARS Smoke", lat, lon, OnGround=1)
      самолёт > 60 NM / smoke_stop / 90 мин / выход из MSFS ──▶ AIRemoveObject
SimObject "ACARS Smoke" ──ACARS_Smoke.xml──▶ ASOBO_GT_FX на узле ACARS_SMOKE_ROOT ──FX_GUID──▶ эффект acars_smoke
```

Ветер мост не передаёт: снос дыма — только работа самого эффекта (узел `WindDirection` в графе эффекта).
Поэтому эффект нужно собрать так, чтобы он реагировал на ветер (шаг 2).

## 0. Что понадобится

- MSFS 2024 с включённым Developer Mode (Options → General Options → Developers → Developer Mode).
- MSFS 2024 SDK (DevMode → Help → SDK Installer). Внутри SDK есть пример **SimpleFX** («Engine Smoke»): это
  готовый дым, с него удобно начать.
- Мост, собранный с SimConnect: `pnpm bridge:build`. В выводе сборки должна быть строка
  `acars-msfs-bridge: SimConnect support ON (…)`. Если там OFF — укажите SDK: `dotnet build bridge/msfs -p:MsfsSdk="C:\MSFS 2024 SDK"`.
- Приложение (`pnpm desktop`) с включёнными живыми данными: без METAR сценарий не запустится.
- План SimBrief, в котором есть **плановая ВПП назначения** и **запасной** аэродром.

## 1. Проверить, что эффект вообще играет (без нашего пакета)

Цель — убедиться, что VFX Editor и спавн работают, прежде чем что-то собирать.

1. Запустите любой полёт, на земле или в воздухе. Открывать редактор в главном меню нельзя.
2. DevMode → File → Open project… → `SimpleFX.xml` из папки примеров SDK. В Project Editor →
   **Build All In Project**.
3. View → **VFX Templates / Instances Debugger** → вкладка **Spawner** → выберите свой самолёт и contact point →
   **Spawn**.

**Ожидается:** у самолёта появляется дым из примера. Если дыма нет, дальше идти бессмысленно: проблема в
SDK или DevMode, а не в нашем пакете.

## 2. Сделать эффект дыма

1. Создайте рабочий проект **вне репозитория**, например `C:\msfs-projects\acars-smoke\`: DevMode → File → New project.
   Имя пакета — `acars-smoke`.
2. Project Editor → **Add Package** → тип **Visual Effect** → имя `acars-smoke` → **Create**.
3. В Visual Effects Wizard назовите эффект **`acars_smoke`** → **Create Visual Effect**. Сразу сохраните проект
   (Project Editor → Project → Save).
4. Соберите столб дыма. Проще всего взять граф из `EngineSmoke.xml` примера SimpleFX как образец. Параметры:
   - тёмно-серый дым, у основания около 50 м в ширину, высотой около 300 м, частицы поднимаются медленно;
   - эффект бесконечный, без конца по времени: объект живёт до 90 минут, мост убирает его сам;
   - **ветер:** добавьте узел **`WindDirection`** (правый клик в Node Graph, поиск «wind»), в Inspector выберите
     опцию `Raw`: это вектор направления и скорости ветра в ft/s. Подайте его в скорость или силу частиц.
     Через какой узел-блок его подключать, документация не говорит **[?]**: выберите вариант, при котором
     дым видимо наклоняется.
5. Проверьте эффект на своём самолёте так же, как в шаге 1.3 (Spawner или спавн из Inspector). Попробуйте
   разный ветер (Weather → Preset с ветром 15–25 kt): столб должен наклоняться **по ветру**, то есть уходить
   в сторону, противоположную той, откуда дует ветер.
6. Visual Effects Editor → File → **Save**.
7. Запишите **InstanceID** эффекта. Он есть в Template/Instances Debugger на вкладке **Asset Packages** или в
   атрибуте `InstanceID` элемента `<VisualEffect.VisualEffect>` в сохранённом `acars_smoke.xml`.
   Вид: `{XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX}`.

## 3. Добавить SimObject и собрать пакет

1. Скопируйте `bridge/msfs/package/PackageSources/SimObjects/` в `PackageSources` рабочего проекта, рядом с
   созданной редактором папкой эффекта. Наш `VisualEffectLibs/ACARS/acars_smoke.vfxlib` **не копируйте**:
   редактор уже создал свой `.vfxlib` с эффектом.
2. В скопированном `SimObjects/Airplanes/ACARS_Smoke/model/ACARS_Smoke.xml` замените
   `{00000000-0000-0000-0000-000000000000}` в `<FX_GUID>` на InstanceID из шага 2.7.
3. В Project Editor добавьте в пакет `acars-smoke` вторую группу ассетов для SimObject и укажите её исходную
   папку `PackageSources\SimObjects\Airplanes\ACARS_Smoke`. Как называется тип группы для немодульного
   `aircraft.cfg` в 2024, не проверено **[?]**: возьмите тип из списка, подходящий для SimObject/Aircraft.
4. **Build All In Project**. Смотрите в консоль DevMode: ошибки сборки glTF (модель — один невидимый
   треугольник, написанный вручную) или ошибки `aircraft.cfg`. Запишите их дословно.
5. Готовый пакет лежит в `Packages\acars-smoke` рядом с файлом проекта. Скопируйте его в папку **Community**
   (путь — Options → General Options → Developers, «Community folder», или в `UserCfg.opt`, строка
   `InstalledPackagesPath`). Перезапустите MSFS.

**Проверка:** DevMode → Aircraft Selector — есть ли в списке `ACARS Smoke` **[?]**. Если симулятор требует
пресет самолёта, лётную модель или ещё что-то, запишите, что именно, и что добавили, чтобы он появился.
Если `ACARS Smoke` нет в списке, мост не сможет создать объект.

## 4. Подготовить полёт

Сценарий `dest_fire` срабатывает сам с вероятностью 2 % за 120 NM до назначения. Для проверки его
запускают вручную, но **условия сценария должны выполняться**:

| Условие | Как обеспечить |
|---|---|
| фаза `CRUISE` или `DESCENT` | быть в воздухе после набора, в крейсере или в снижении |
| нет диверсии | не отвечать `DIVERT` в других сценариях этого рейса |
| `ofp.dest_rwy` | в плане SimBrief выбрана ВПП назначения |
| `ofp.altn` | в плане есть запасной |
| `wx.dest_smoke_drift` | в METAR назначения есть ветер с направлением: `27012KT` годится, а `00000KT` (штиль) и `VRB03KT` — нет |

Удобнее всего короткий рейс на 80–150 NM: до 40 NM лететь недолго. Пример — EFHK–EETN, если в METAR Таллина
ветер не переменный. Погоду в MSFS ставьте **Live**: тогда снос в симуляторе совпадёт с ветром из METAR,
который пишется в телексе.

Порядок запуска:
1. MSFS, полёт на стоянке.
2. Мост: `bridge\msfs\src\AcarsBridge\bin\Debug\net10.0\acars-msfs-bridge.exe` (по желанию с `--verbose`).
   Окно не закрывать.
3. `pnpm desktop` → в статусе мост подключён, источник `simconnect`.
4. Загрузить OFP, начать рейс, логон и FLT NBR — как обычно.

## 5. Запустить пожар и посмотреть дым

1. В крейсере или в снижении: окно рейса → «Нестандартное событие» → **Пожар у ВПП назначения** →
   **Запустить сейчас**.
2. **Ожидается в ленте:** «Запущено вручную: dest_fire», затем телекс `FIRE REPORTED NEAR RWY …`, в нём
   `SMOKE DRIFTING <румб>, WIND <ddd>/<nn>KT`. Если сценарий не стартовал, в ленте написано, какое условие
   не выполнено.
3. **Ошибок в ленте быть не должно.** Возможные строки «Команда симулятору smoke не выполнена» и что они значат:
   - `no planned runway in the OFP` — в плане нет ВПП;
   - `no coordinates for XXXX RWY nn` — ВПП нет в OurAirports или нет сети;
   - `unavailable sim not connected` — мост не подключён к MSFS.
4. Ответьте на телекс `HOLD` (или подождите 8 минут: HOLD выбирается по умолчанию). Не отвечайте `DIVERT`:
   дым тогда останется, но вы улетите от него.
5. Подлетайте к аэродрому. На **40 NM** мост создаёт объект. Ошибка SimConnect видна в статусе моста в
   приложении как `simconnect exception CREATE_OBJECT_FAILED …`. Это **статус**, а не строка ленты:
   `README.md` в этом месте неточен.
6. Посмотрите на ВПП: с дальней дистанции, на 20–30 NM, и вблизи, на подходе.

**Что записать (результат проверки):**
- [ ] дым стоит у **середины плановой ВПП**, а не в стороне и не в воздухе (проверка `Altitude = 0` + `OnGround = 1`);
- [ ] виден издалека: с какого расстояния заметен;
- [ ] наклонён **по ветру**, в сторону румба из телекса (`SMOKE DRIFTING …`);
- [ ] играет ли эффект на объекте, которым никто не управляет (на форумах об этом пишут разное) **[?]**;
- [ ] FPS: значение в 20–30 NM от аэродрома без дыма (до 40 NM) и с дымом, по счётчику DevMode или своему оверлею;
- [ ] через 20 минут HOLD приходит телекс `FIRE NEAR RWY … UNDER CONTROL` и **дым исчезает**.

## 6. Проверить, что дым убирается

Каждый случай — отдельный короткий тест (можно на том же аэродроме):
1. **По сценарию** — после «UNDER CONTROL» (шаг 5).
2. **Удаление больше 60 NM** — запустить пожар, подлететь ближе 40 NM (дым появился), отлететь дальше 60 NM, вернуться:
   дым должен исчезнуть, а на 40 NM появиться снова.
3. **Остановка рейса** в приложении — дым исчезает.
4. **Выход из MSFS** при живом дыме, затем новый запуск и полёт к тому же аэродрому: мост создаёт дым заново,
   потому что запрос ещё действует (до 90 минут или до остановки рейса).

## Если что-то не так

| Симптом | Где смотреть |
|---|---|
| `ACARS Smoke` нет в Aircraft Selector | шаг 3: тип группы ассетов, ошибки `aircraft.cfg` или glTF в консоли сборки |
| `CREATE_OBJECT_FAILED` в статусе моста | заголовок `title = "ACARS Smoke"` не найден: пакет не в Community или не собран |
| объект создан (ошибок нет), а дыма нет | `FX_GUID` (шаг 3.2), есть ли в 2024 `Asobo\Generic\FX.xml` и шаблон `ASOBO_GT_FX` **[?]**; VFX Instances Debugger — появился ли экземпляр эффекта |
| дым под землёй или в воздухе | как MSFS считает `Altitude` при `OnGround = 1` **[?]**: запишите, на какой высоте он стоит |
| дым вертикальный при сильном ветре | граф эффекта без `WindDirection` (шаг 2.4) |

## Что прислать после проверки

Ответы по чек-листу шага 5, дословные ошибки сборки и SimConnect, если были, скриншот дыма с расстояния и
вблизи, FPS «до/после». Если ради пакета что-то меняли (тип группы, пресет, `aircraft.cfg`, XML), пришлите
изменённые файлы: их нужно вернуть в `bridge/msfs/package/`, а InstanceID — в `ACARS_Smoke.xml` в репозитории.
